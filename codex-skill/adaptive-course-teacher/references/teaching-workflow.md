# Teaching Workflow

## Before Viewing

Gather the transcript and metadata first. Inspect the original lesson page and discussion area when the learner has authorized logged-in browser access.

Extract only:

- The problem the lesson solves.
- The final result the learner should recognize.
- Load-bearing concepts and actions.
- Sections that are demonstrations, deliberate mistakes, cleanup, or safe to skim.
- Recurring learner confusion, version differences, and instructor corrections.

Define the smallest observable result for this lesson. If the goal involves production rather than recognition, decide what the learner must do without prompts before calling it learned.

Give a short viewing map with timestamps when verified. Do not create durable notes yet.

## After Casual Viewing

Assume the learner understood some parts, missed some parts, and spent working memory on listening or interface tracking.

Reconstruct:

1. What must be understood and why.
2. The instructor's reusable experience and the failure it prevents.
3. Operations, parameters, or shortcuts worth retaining.
4. Details that can remain lookup knowledge.

Explain the reasoning again. A terse list of omitted nouns is not enough for recall.

Do not infer mastery from familiarity, recognition, copying, or a guided demonstration when the intended outcome is independent performance.

## Decide the Artifact

- Durable definition, rule, table, or checklist: Markdown note.
- UI location or fixed comparison: static screenshot.
- Short procedure or visible state change: animated WebP.
- Spatial orientation, causal order, or variable comparison: interactive HTML.
- Connected topic structure: suggest a mind map; let the learner place it when layout matters.

Ask the learner which recommendations should become durable artifacts. Do not save everything merely because it was mentioned.

## Practice and Assessment

Separate teaching from assessment:

1. Demonstrate or expose prerequisite information once.
2. Remove answer-bearing prompts before independent recall or execution.
3. Let the learner attempt retrieval before revealing the answer.
4. Give specific correction tied to the observed error.
5. Record the result under the capability actually tested.

Track dimensions independently when they can diverge, such as recognition versus production, guided versus independent execution, correctness versus presentation, or conceptual explanation versus tool fluency. One strong dimension must not mask another weak one.

Use repetition only while attention and quality remain useful. For skills that benefit from spaced retrieval, schedule the next attempt from observed accuracy and effort rather than advancing on a fixed calendar alone.

## Follow-Along Notes

Use numbered steps only for a true sequence. Each step contains:

- Exact mode and UI context.
- Exact action from the source.
- A small observable checkpoint.

Place added advice under `Optional`, `Version adaptation`, or `If this fails`. Never blend it into the instructor's procedure.

## Shortcut Memory

Track shortcuts as `key + mode/editor/context + function`. The same key can mean different things in different modes. Record whether the learner already knows it, rejected it, or wants to retain it.

Recommend a shortcut only when it removes recurring friction or captures valuable expert workflow. Explain why it matters in practice.

## Close the Lesson

Record the source, intended outcome, independent result, recurring error, learner feedback, created artifacts, and next useful review or lesson. Update stable preferences only after they are supported by feedback; keep temporary experiments in the lesson record.

Choose the next lesson from this evidence. Do not generate a long permanent sequence merely because a syllabus exists.
